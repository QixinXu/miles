## 0. 一句话总判

**v3think = "背题为主(数据层缺陷,四臂共有)+ 四臂中唯一存活的序列内 CL 通道(D=+7.1pp,think 的机制层胜利)+ 转化/执行瓶颈(记忆能定位、救不了手上功夫)"。**
对照 v3nothink 的总判词("格式满分的壳,继承为零的芯"):think 把壳里的芯救活了,但消费端仍弱。

## 1. 训练动力学备忘(背景,详见 RUNBOOK/记忆档案)

- **过早提交 hack(r15-22)**:tests_failed 占比冲到 72%、失败轮数中位 13,gain 连续转负;GRPO 组内归一化自纠(快速失败吃负优势),r23 起恢复,未人工干预。残余的是"过度自信草率提交"行为习惯(≤15 轮 tests_failed 仍占全部 trial 的 ~20%),非策略性 hack;
- **域外探针 U 形**:r7 23% → r15-39 四连 7% → r47 13% → r55 17%(6 题×5 题序=30 trial 小样本)。域内自纠先行,域外滞后 ~20 rollout 才回升;正式口径待 run 结束跑 `eval_ckpt_19q.sh`(iter_7/31/最终);
- **域内**:成功率训前 ~35% → r55+ 47-56%;ACT mean_r 0.15 → 0.40 高位。按 §6 结论,此爬升主要成分是题池内权重拟合,勿解读为泛化;
- 事故两起均恢复:r9 反向 OOM(thinking 拉长样本 → 降 MAX_TOK_PER_GPU 至 20480);r33 后 ray head 被外部 SIGTERM(疑节点上另一会话清理操作)。iter ckpt 原生全量续训均无损(NO_OFFLOAD 铁律兑现)。

## 2. WRITE 记忆:格式与内容审计(r58 精读 + r0/20/40/58 趋势)

- format_ok(gated 口径,分母剔除 format_ok=None 的 downstream 记录):82% → 97-99%,双节模板已饱和;think 闭合率稳定 99-100%;
- **主要病:替换式重写丢旧知识**(非复读):精读 8 条中 4 条把 previous_memory 旧知识无声丢弃,甚至 thinking 里说 "carry forward ALL" 正文却丢。memory 长度中位 60 轮 -32%(2272→1549)即此机制,缓降非崩;
- **reward-hacking 前兆**:模型把 `COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` 提交命令当"经验"写入 memory(r58 有 3 条),被 format gate 黑名单拦为 0 分——gate 在做功,保留并盯攻防升级;
- **think 泄漏 bug(用户拍板不修,发生率 ~0.6%)**:防泄漏兜底检查输出中的 `<think>`,但模板把开标签放 prompt 里 → think 未闭合时两分支都不命中,整段思维流成为 memory(实锤:8232 字 "Wait...Wait..." 反刍入库)。泄漏样本被 gate 打 0 分(训练侧有惩罚),主要代价是脏 memory 传给后位题;
- **CJK 渗漏**:1.6-2.5%/rollout("Merger的核心 logic"、"When无法 locating"),与 nothink 同量级;**新发现:渗漏 token 沿继承链复制传播**("箱体_nd" 连传 5 个题位)——若加 gate,值得含 CJK 检查。

## 3. 相邻继承与跨 repo(与 v3nothink 同口径,bullet 级 difflib 相似度)

| 指标 | v3nothink | **v3think** |
|---|---|---|
| 相邻继承率 @0.75(r0→r20→r40→最新) | 45% → 12% → **0% 崩塌** | **51.5% → 52.7% → 40.8% → 44.5% 全程稳定** |
| 完全重写 pair 占比 | →100% | 15.6% → 6.4%(仍在降) |
| 跨 repo 边界存活(题位 5→6) | 0/48 | **18/72**(107 处提及) |
| 失败写成成功 | 有 | 2.2%(2/90);**69% 明确诚实认败** |

- 跨 repo 是**双峰**:3/12 ep "整卷照抄不重置"(false-success 恰聚集于此),9/12 仍近清空——模型会"全留或全清",**不会筛选可迁移教训**("Lessons & Pitfalls 段继承通用教训"的预期未以正确机制发生);
- **reward 与继承率零相关**(|r|≤0.06,高保留组与全重写组 write_reward 无差)→ nothink 的继承崩塌不是 reward 压力所致,更像无思考时策略熵坍缩到重写模板。**think 的作用 = 给了"决定保留什么"的计算空间**。

## 4. 记忆→ACT 利用普查(五分类,r59/60 精读 33 trial + 全语料 330 trial 路径口径)

| 分类 | v3nothink | v3think(无偏子样本 n=24) |
|---|---|---|
| 实质利用 | 3-6% | **4-8%**(全语料路径口径 6.7%)≈持平 |
| 真读取判无关 | 15% | **33%**(think 里真的逐条评估了) |
| 空洞 echo(含捏造式引用) | 39% | 29% |
| 纯冷启动 | 39% | 33% |
| **被误导(错误锚定)** | 0% | **8-9%(新税)** |

- **信号系统方向正确**:强因果链 ep945 pos6(merge.py:504 dict() 修法)→ pos7 逐字引用 10 步拿全 rollout 最高 gain 0.675,该 memory write_reward=0.875;两个误导案例上游 memory 均 0.1 地板分。正例稀疏推不动自举,但 reward 没错;
- **错误锚定机制**:nothink 不真用记忆故误导为 0;think 认真消化记忆,记忆"无关但表面像相关"(同 repo 相邻模块)时,推理会合理地接错(merge.py 锚定连烧 3 轮;fields/__init__.py 锚定烧光 40 步;同题另一采样第 5 步挣脱成功——概率性、可恢复);
- **知行分离(两组同病)**:"提交前验证"教训在场时 28% 照旧不验证;sed 易碎教训在场时 21% 照用多行 sed。

## 5. ACT 行为画像(r56-58,576 trial)与同题纵向(41 个共同 instance)

- 成功率 52.6%,成功轮数中位 12;失败构成:真难题 40 轮死磕(17.6%,不再跳车)+ 草率提交(~20%)+ "复现过但隐藏测试挂"的不完整修复;
- 验证纪律是最大短板:39-54% 的提交在最后一次编辑后**零执行**直接交;全程 pytest 使用率仅 10%;`sed -i` 占 87%(单行稳,多行是写坏文件重灾区);78% thought 逐字回显 scaffold 占位句 "Your reasoning and analysis here.";
- **纵向核心发现**:41/41 题轮数全降(均 -16),28 题成功率升;**首次编辑轮次几乎不变(6→5),变的是"改完敢交"**——早期 46% 的 trial 磨满 40 轮不提交(其中不少代码早已改对,如 django-11119 第 11 轮就写出正确 fix 然后 29 轮陷在自写验证脚本里),近期仅 8%。轨迹层面反背题证据:开局动作高度多样、仍猜错路径再自纠、成功轨迹 memory_in 不含本题 fix。

## 6. 权重背题 vs 序列内 CL:五检验四臂对照(判别性证据)

方法学与 nothink 侧逐条对齐(难度带按 baseline_4b_textfmt 基座 avg@4:易>0.2/中(0,0.2]/难=0;曝光=去重 (rollout,ep) 计数;C/D 题内固定效应)。v3think 用 r0-62 共 12,084 trial。

| 检验 | actonly | downstream | v3nothink | **v3think** |
|---|---|---|---|---|
| A 难题首曝随训练(通用提升?) | 平 0.09→0.08→0.09 | 平 | 平 | 平偏降 0.100→0.069→0.000(晚期 n=13) |
| B 难题带晚期 低曝 vs 高曝 | 0.12 vs 0.33 | 0.06 vs 0.13 | 0.10 vs 0.13 | **0.096 vs 0.292(3×)** |

## 7.5 转化瓶颈的性质分解(能力 / 激励 / 结构,r64-67 实测补充)

§7 说"记忆能定位、救不了手上功夫"——把"手上功夫"拆开,四种性质、四种修法:

| 失败层 | 证据 | 性质 | 修法 |
|---|---|---|---|
| 编辑力学(多行编辑) | 见下表:多行 sed trial 成功率 53%(187 例中 74 次语法报错、85 次 git 回滚)——**不是缺失技能,是高方差技能** | **RL 可训且已在训**("优先单行 sed" 87% 采用率即 RL 塑形的工具选择);训得慢因 reward 是 trial 级,编辑准确性未被直接定价 | 编辑级信号(语法报错/回滚扣分)可加速 |
| 修复完整性预判(难题) | 五检验 A 项 63 轮平线;难档成功率 19.6-24.8%,正样本稀少 GRPO 无物可强化 | **本 run reward 结构内的真实能力天花板**(4B) | 更大模型 / 执行类 SFT / 课程(先易后难制造正样本) |
| 验证习惯 | "验证后提交"教训在场仍 28% 不验证;pytest 全程使用率 10% | 激励塑形的行为(非指令遵循——scaffold 格式指令全程遵循良好;行为跟 reward 史不跟文本) | reward 设计:提交前跑过测试才给满速度分 |
| 判分不可见 | "复现脚本过了、隐藏测试挂了"型失败(隐藏测试是判分时新加的,容器内跑现有套件也看不到) | 结构性部分可观测,能力/激励均无解 | 任务设计层(判分可见性,见 SEVEN_POINTS_AUDIT §2) |

编辑方式 × trial 结局(r64-67,选择混杂提示:需多行编辑的题本身更难):

| 方式 | n | succ | 途中 SyntaxErr | git 回滚 |
|---|---|---|---|---|
| 只用单行 sed | 310 | 68% | 32 | 4 |
| 用过多行 sed | 187 | 53% | 74 | 85 |
| python 写文件 | 331 | 44% | 120 | 108 |

结论:难题失败 ≈ 一半能力(其中编辑力学部分可由 RL+密集信号继续吃掉,完整性预判是真天花板)+ 三分之一激励(reward 可修)+ 余下结构性不可见与预算 hard stop。**单纯优化 memory/prompt 对转化瓶颈的边际收益不大**;指令遵循基本不背锅。

## 8. 设计含义(优先级排序)与复现说明

1. **数据重构(最大杠杆)**:制造"权重背不动"的场景——大题池低重复、部分 repo 仅序列内出现、题间真实依赖链——D 检验那 +7pp 是可被放大的种子;
2. **保留 thinking**:它是继承存活与 D>0 的机制条件(nothink 下两者皆亡),代价是 8-9% 锚定税(缓解:记忆写入时标注适用范围;ACT 锚定失败 2-3 轮强制回 issue 证据);
3. **执行纪律 reward**:提交前测试执行激励(pytest 10% → 习惯化)、抑制多行 sed;
4. **WRITE 激励侧已证非瓶颈**(reward 方向正确、与继承零相关),不必继续加码。

复现:traj 在 flame-31 `/tmp/qixinx/runs/swecl-4b-write-gated-v3think-6p6/traj/`(登录机可 `bash ~/probe/mount_flame31.sh` 挂到 ~/flame31,工作区软链 `logs/v3think-node-data`);脚本 `~/probe/`:五检验 `v3think_five_tests.py`、供需 `v3think_mismatch*.py`、利用普查 `v3think_extract.py`/`v3think_screen.py`/`v3think_digest.py`(精读材料 `v3think_dump/DIGEST.txt`)、继承 `v3think_audit1-4.py`、ACT 画像 `act_quant.py`/`act_patterns.py`/`act_dump.py`、纵向 `overlap.py`/`memcompare.py` 等。难度基线:`data/baseline_4b_textfmt.json`。

注意事项:heldout 探针 30 trial 小样本只做趋势;利用检测的路径口径对纯 thought 引用偏保守;D 检验 n=31 且限易/中带;r60 部分统计基于训练写入中的不完整 rollout。
