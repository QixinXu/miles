Setup, in one paragraph: during training the model works through episodes of 12 bug-fixing tasks. Each episode spans two repositories (6 tasks in one, then 6 in another). After every task the model rewrites a persistent notes file ("memory") that is shown to it at the start of the next task; the notes carry across the repository switch and reset only between episodes. In the gated run the notes-writing step is trained with reinforcement learning (rewarded when the next task succeeds); in the act-only run the same notes are written but never trained — it is the control. Both runs saw the same tasks in the same order and start from the same base model, so any divergence is caused by training the notes-writer.

### Lessons & Pitfalls
- String formatting error: `Duplicate %s parameter.*param` is incorrect - using string multiplication `*` instead of format `%` causes the error message to show repeated string content instead of actual parameter name
- For duplicate parameter error messages, use `'Duplicate %s parameter.' % param` - not `'* param` or multiplication
- When validating duplicate parameters, check for: client_id, grant_type, redirect_uri, response_type, scope, state
- Always verify test passes after fixing string formatting issues in error messages

When the model finished a task about URI parsing, its rewrite deleted the notes about the previous task (grant dispatchers) and replaced them with notes about the current one. Old entries are not merged or kept — the notes behave like a sticky note about the last task, rewritten each time, rather than a notebook that grows.

- - This class handles routing authorization code token requests to either default_grant or oidc_grant based on scopes
- - `AuthorizationTokenGrantDispatcher._handler_for_request` had reachable code bug - the actual logic for checking 'openid' in scopes was unreachable due to incorrect if-else structure with early return
- - The scopes extraction needs to happen BEFORE the handler selection - formatting as `scopes = self.request_validator.get_authorization_code_scopes(...)` then checking if 'openid' in scopes
- - When fixing `AuthorizationTokenGrantDispatcher`, consider that `request_validator.get_authorization_code_scopes()` requires specific parameters (client_id, code, redirect_uri, request) - ensure these are correctly extracted from the request object
- - The handler selection must properly check for 'openid' in scopes before falling back to default_grant - incorrect order causes OpenID Connect requests to be handled by OAuth2 handler instead
+ - Key file `host_from_uri` function is located in `oauthlib/oauth2/rfc6749/utils.py`
+ - Key utilities for OAuth functions are in `oauthlib/oauth2/rfc6749/utils.py`
+ - When fixing URI parsing functions like `host_from_uri`, ensure all variables are defined BEFORE the return statement - reordering code to place variable assignment before return is critical
+ - The `host_from_uri` function requires proper logic flow: parse URI with urlparse first, then handle port extraction and default ports, then return - this must be in sequence

+ - Check if function has forward/backward references - return statement should not come before variable assignments that it depends on

Honest caveats

1) The control also drifts late: its old-repository keep-rate falls from 24% (r60-70) to 11% (r80-98). The gated run's fall is to 0.5% — twenty times lower — and every other measure (size, growth, deletion rate) moves only in the gated run, so the effect of training the notes-writer is clear, but "perfect notebook vs no notebook" would be an overstatement. 2) Even at its best (r40-50) the gated run kept old-repository notes in only 28% of episodes — accumulation was never the dominant behavior; training then eliminated it. 3) Keep-rate is measured by whether the old repository's name still appears anywhere in the final notes — a lenient test, which makes the 0.5% figure more damning, not less.
