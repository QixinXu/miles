# smith-4b-gated-v3think-v2 训练中期 Case Study:memory 演化与 ACT 能力习得

*2026-07-23 分析(覆盖 rollout 0–95)· 2026-07-24 讨论后补充 §5.1–5.3 · 三个独立分析 agent,~4,200 trial 全量统计 + 60+ 个 trial/memory-pair 逐轮精读*
*(该 run 已于 07-24 完成 120/120;收官 heldout r119=10%,全程 15 点均值 ~14% 无净迁移,终档 iter_0000119 落盘)*

## 0. 执行摘要

**一句话:这次 RL 把模型从"谨慎但常淹死的探索者"训成了"高效但从不验证的快枪手";reward 涨的主要来源是提交纪律和步数效率,不是修 bug 能力;而 memory 的跨任务积累功能在训练中被彻底优化掉了。**

| 维度 | 结论 | 关键证据 |
|---|---|---|
| memory 格式 | ✅ 显著提升 | format_ok 61.5%→83.9%,前言回显 21.9%→0.1% |
| memory 跨任务积累 | ❌ **崩塌** | 相邻继承率 51%→0%,Lessons 存续率 0.43→0.004,换 repo 旧页保留 36%→0% |
| ACT 提交纪律/效率 | ✅ 最强增益 | 未提交 46.5%→3.0%,成功中位轮数 21→6,命令循环 41%→10% |
| ACT 定位/编辑技巧 | ✅ 真实提升 | 首命令 grep 化 6%→47%,sed 失败率 15.5%→7.6%,编辑失败换招 |
| ACT 验证纪律 | ❌ **被训掉** | 改后运行验证 80%→5%,pytest 42%→1.7%,零验证提交 86% |
| 修 bug 硬能力 | ➖ 无净提升 | 成功率 24.6%→30.7%(中期峰值)→19.6%;分档全线未涨 |
| 晚期策略健康 | ⚠️ 坍缩信号 | 63% 轮次 thought 为模板占位句(r80 后突变),empty_patch ×3,mean reward 低于中期 |

## 1. 方法

- **数据**:`smith-4b-gated-v3think-v2` 训练轨迹(v2 数据:333 条 6+6 episode/33 repo,随机抽取;gated_downstream + WRITE prompt v3 + WRITE thinking)。
- **窗口**:早期 r0–6(1,344 trial)、中期 r44–50(1,344)、晚期 r88–95(1,536);行为指标为全量统计(非抽样),配置三窗口一致(max_steps=40 等)。
- **精读**:memory 相邻对 40+(三阶段各 ≥14 对);ACT 完整 trial 23 个(含早晚同策略对照)。
- **已知混杂与处理**:①reward 带步数折扣——同轮数分桶后早晚成功 reward 几乎相同,故 reward|成功 的上涨是"变短"的机械结果;②每窗口仅 14–16 个不同 episode(×8 siblings),**跨窗口成功率差异置信度有限**;但行为指标(轮数/提交率/验证率/模板化)在 107 个 rollout 上单调且幅度巨大,是稳健结论;③分档成功率控制难度构成,排除"晚期抽到更难题"的方向性解释。

## 2. memory 质量演化:表层提升,核心功能崩塌

### 2.1 格式(提升)

| 指标 | 早 r0-4 | 中 r44-48 | 晚 r90-95 |
|---|---|---|---|
| format_ok | 61.5% | 74.2% | 83.9% |
| 前言回显率 | 21.9% | 0.0% | 0.1% |
| markdown fence 率 | 16.7% | 0.2% | 1.3% |
| CJK/乱码渗漏 | 1.0% | 0.9% | 0.3% |

gated reward 的 format 门控确实起效。晚期残余的格式失败几乎全是新病:**think 循环推理耗尽 2048 token → `</think>` 未闭合 → 整段 CoT 泄漏为 memory**(1.6%),下游一题拿到的"记忆"是自言自语(rollout_93/ep_1488 T4)。

### 2.2 跨任务积累(崩塌,本报告核心发现)

| 指标 | 早 | 中 | 晚 |
|---|---|---|---|
| 相邻继承(bullet 保留>50%) | **51.1%** | 0.6% | **0.0%** |
| 替换重写(<20%) | 34.9% | 97.6% | 96.4% |
| Lessons 节保留率(均值) | 0.426 | 0.005 | 0.004 |
| 换 repo 时旧 repo 知识保留 | 36% | 1% | **0%** |
| bullet 数均值 / 长度中位 | 16.6 / 2553 | 7.9 / 1011 | 4.9 / 958 |

早期存在教科书式积累链(sqlfluff 连题 bullet 10→30 逐题合并、保留率 0.70→1.00,并显式做新旧合并);晚期链条实测**每步保留率 0.00**,memory 退化为"窗口=1 的单题事后总结 + 万能口号"("Always run the full test suite before submission" 在晚期几乎每条出现——而 ACT 完全不执行它,见 §4.3)。同 repo 已确认的事实(测试怎么跑、关键文件位置)不再复现。

**归因**:这是 gated_downstream 的捷径收敛。下游 ACT 只需要"上一题的定位指针"就能拿到 reward,积累的长记忆没有边际收益且消耗生成预算;prompt 中"do NOT delete a confirmed fact"的要求没有 reward 背书,于是被系统性违反。7-21 首次审计(r0-12)看到的 47% 替换重写是这条滑坡的起点,训练把它推到了 ~97%。

### 2.3 内容病(低位持平)

- "测试是错的"类有害教训:0.9%→1.1%→0.7%,未消除;
- 假设硬化(think 里的猜测写成 memory 断言):三阶段均在,典型如 pdfminer CMap 案例(think 自述 budget 耗尽、"likely" 是猜测,memory 写成断言事实);晚期因 memory 不再传承,污染半径反而变小——病还在,只是宿主死了;
- 行号级过度锚定 7.3%→4.7%(略降)。

## 3. ACT 行为演化:全量指标

| 指标 | 早 r0-6 | 中 r44-50 | 晚 r88-95 |
|---|---|---|---|
| 成功率(±SE) | 24.6±2.6 | **30.7±3.1** | 19.6±2.3 |
| 分档 easy/mid/hard | 37.7/29.0/10.0 | 54.5/25.0/14.3 | 36.3/14.3/9.6 |
| 未提交率 | 46.5% | 19.7% | **3.0%** |
| tests_failed | 18.5% | 41.7% | **67.8%** |
| empty_patch | 2.2% | 0.9% | 6.0% |
| 提交率 | 45.4% | 73.8% | 95.2% |
| 成功中位轮数 | 21 | 10 | **6** |
| 提交前 pytest | 42.3% | 7.7% | **1.7%** |
| 改后运行验证 | **80.2%** | 69.4% | **5.2%** |
| 零验证提交 | 6.4% | 26.8% | **86.0%** |
| 验证者 vs 非验证者成功率 | 58.9 vs 42.7 | 47.1 vs 29.4 | 18.7 vs 20.9(无差异) |
| 首命令 find/grep | 76%/6% | 52%/12% | 24%/**47%** |
| 编辑命令数/trial | 7.46 | 3.98 | 2.04 |
| ≥3 连相同命令的 trial | 41% | — | 10% |
| thought 模板占位句率 | 0.1% | 0.1% | **63.2%**(轮次口径;trial 口径 93%) |

三条主线:
1. **失败模式完全反转**:早期失败 63% 是"探索至死不提交"(含"修好了却掉进自建测试兔子洞"的典型死法);晚期失败 67% 是"≤12 步投机提交挂测试"。RL 治好了旧病、换上了新病。
2. **验证的价值随验证的消失而消失**:早中期"提交前验证"带来 +16~18pp 成功率;晚期残存的验证已是走形式,增益归零。
3. **中期(r44-50)是这条 reward 曲线上的甜点**:成功率峰值 30.7%、验证还剩 69%、提交纪律已立;晚期属于过优化(mean reward 0.212→0.159 也支持)。

## 4. 学到的新模式(定性,带早期对照验证)

### 4.1 正面
- **P1 先立论后开枪**:晚期成功 trial 的 turn 0 仅凭 issue 文本给出完整因果假设 + 直奔目标 grep(晚期精读成功 8 例中 7 例;早期 0 例,一律"先探索仓库结构");假设错误时 1 步内改道。
- **P2 注入伤疤识别(分布先验)**:UnboundLocalError→秒诊"分支缺赋值"(remove_assign 注入方式);"return 在函数体/docstring 之前"→秒诊 combine_module。**注意:这是对 SWE-smith 靶场的记忆,域外迁移性存疑**——与 heldout(swecl)全程 ~14% 平移不涨相互印证。
- **P3 编辑纪律**:heredoc 整块替换为默认手段(53%→54% 但用法变准),sed 用于行号级插入,编辑失败立即换招不恋战(8 连发相同失败命令的早期行为消失)。
- **P4 memory 定位捷径**:memory 路径在前 3 轮被复用的比例 7%→17%(基数小);memory 误导时 2-3 步内自行改道,不再引发全库漫游。

### 4.2 被推翻的候选(方向相反)
- "先写复现脚本"、"提交前跑 pytest 并解读输出"都是**早期**行为(60%/42%),被 step 折扣 reward 定价出局(16%/1.7%)。

### 4.3 负面
- **N1 投机提交**:晚期主导失败模式(67%);干净案例:memory 明写"Always verify patch application before submission",ACT 4 步裸奔提交挂测试。
- **N2 模板句坍缩**:63% 轮次 thought 以 prompt 占位符"Your reasoning and analysis here:"开头,r60-74 仍 ≤1%、r80-84 跳 55%、r88-92 达 93%——突变式 RL 后期模式坍缩;占位句后的内容仍有实质,但这是策略健康的明确警报。
- **N3 教训选择性遵守**:零成本教训(工具选型)被执行;费步数教训(先验证)7/7 无视——**reward 结构决定了 memory-ACT 传导的过滤器**。

## 5. 综合归因与含义

三个 agent 的发现指向同一个根:**reward 结构(步数折扣 + gated 下游)同时定价掉了"验证"和"记忆积累"这两种前期投资行为**。模型精确地学会了这条 reward 曲线要什么:快、必提交、格式合规;不要什么:跑测试、写长记忆。域内 reward 从 0.115→0.159(中期 0.212),而 swecl heldout 全程 ~14% 平移——涨的是靶场适应,不是能力。

### 5.1 验证行为的定价分析(讨论后定量补充,2026-07-24)

用实测数据核算"验证是否值得"这笔账,证实裁撤是 reward 设计下的**最优解而非退化**:

- **成本端**:成功 trial 的 reward 按轮数分桶——6-10 轮 ≈ 0.81-0.84,11-20 轮 ≈ 0.64-0.66。一套验证仪式(复现脚本 + 跑测试,约 4-10 轮)的步数折扣成本 ≈ **−0.15~0.2 reward**;
- **收益端**:早中期验证者比非验证者成功率高 16-18pp,按成功值 ~0.8 折算,期望收益 ≈ **+0.13 reward**(注意此为相关非严格因果,方向可信);
- **0.13 < 0.15~0.2 → 净亏损**。RL 把账算对了,验证必然被裁。
- **修法刻度**(由此账直接导出):要么把步数折扣调平缓到验证成本 <0.1,要么给"改后运行过代码"一个 ~0.1 量级的显式 bonus——天平即翻回。单纯在 prompt 里写"要验证"没有用(实测:memory 里的验证类教训 7/7 被无视)。

### 5.2 模板坍缩 = 策略熵坍缩(讨论后证据链)【已被 §5.5 部分修正】

占位符回显("Your reasoning and analysis here:")的三重证据指向 RL 后期熵坍缩:
1. **突变而非渐变**:r60-74 ≤1% → r80-84 55% → r88-92 93%,分布锁死的典型时间形态;
2. **配置无抗坍缩项**:`--entropy-coef 0.00`,KL loss 系数仅 0.01——没有任何力量阻止策略熵收缩;thought 不进 reward,该前缀零惩罚,是熵收缩下的"能量最低态";
3. **前科**:v3nothink 组的 memory 继承崩塌(45%→0%)当时亦归因熵坍缩(无 think 时更早发生)。
坍缩的行为学后果在 case 中可见:僵化四步流水线对异常情况(自述"文件已改烂")失去适应性,照常裸奔提交。干预选项:熵 bonus >0 / KL 加大 / 更早停;零成本小修 = format_example 占位句改为不可复读写法。
与 mean reward 曲线互证:中期 0.212 > 晚期 0.159——中期是"纪律已立、熵未死"的甜点区,晚期属过优化。

### 5.3 记忆积累崩塌的结构性归因(与 swecl 对照,讨论后补充)

关键对照:**swecl 旧数据上的 v3think,继承率全程稳定 40-55%(未崩);smith v2 上崩至 0%**。同为 gated+think 配置,差异在数据:

- swecl 240 题反复曝光(中位 32 次)——记住的东西**将来真的会再遇到**,memory 有"答案缓存"的实际价值(此即背题通道);
- smith v2 每条 episode 曝光 ≤1 次、函数 cap=2 保证函数不重复——**下一题永远是全新的**,可迁移的旧知识只剩 repo 布局/测试命令这类"重新探索三步即可拿回"的低价值内容。
- **反背题的数据设计在焊死背题通道的同时,也焊死了记忆积累的大部分客观回报**;残余回报又被窗口=1 的 gated reward 看不见。积累之死是(数据 × reward)组合的结构性结果,与数据"质量"无关。

**幸存内容的选择律**:零执行成本、对任意下一题立即适用、与 repo 无关的教训会存活并传播(本组:"Python scripts are superior for multi-line edits"→ACT 采纳;babel v3curr 组独立观察到同类:sed 用不好 → memory 提出 replace() → ACT 学会使用)。死掉的是 repo 特定事实(收益延迟/不确定)与费步数建议(被 5.1 的账直接裁掉)。

**两个可检验推论**:①babel v3curr(curriculum 数据、结构同 v2)若继承率同样崩塌,则坐实"去重+窗口=1 的结构性结果、与数据版本无关";②要让积累存活:reward 窗口 >1(gated 于 k+1..k+m 合计),或数据具备真实跨题依赖(同子系统连环 bug / 知识链——演化链方向正是对此的回答)。

### 5.5 修正与补充(2026-07-24,MI 离线验证 + 19q 评测后)

**修正一:模板坍缩是"前缀级瞬态",非推理坍缩,且已自愈。** 用 RAGEN-2(arXiv:2604.06268)的互信息思路做了离线验证(TF-IDF 词法代理,批内"从 thought 反查源题",数据 notes/mi_probe_smithv2.csv):Retrieval-Acc 全程 0.92-1.00(随机水平 0.042),占位句高峰期(r88-100)thought 仍精确引用本题专名——**推理内容的输入依赖度从未坍缩**,占位句只是句首 tic。且 echo 率是 r84-104 的瞬态发作(峰值 ~82%@r100,统一口径),**r108 后回落、r116-119 仅 ~1% 自愈**。本报告 §4.3-N2 的"93% 坍缩"系分析窗口(截至 r95)恰落在发作期内所致,严重度降级;§5.2 的熵坍缩解释对"前缀 tic 的出现"仍成立,但其危害性判断收回。MI 型指标对此类前缀 tic 不敏感属预期(它测的是内容级依赖),词法版监控收益有限;RAGEN-2 的 SNR 过滤依据(梯度效率)不受此修正影响。

**修正二:"中期 ckpt 更强"被 19q 评测证伪;真实故事是"本体变强、记忆变害"。** Megatron 加载式 19q 评测(replace=19题×5题序 n=95;stateless=no_memory×avg@4 n≈76):

| 19q 成功率 | replace(带 memory) | stateless | memory 增益 |
|---|---|---|---|
| iter_47 | 22.1% (21/95) | 17.3% (13/75) | +4.8pp |
| iter_119 | 21.1% (20/95) | 25.0% (19/76) | **−3.9pp** |

裸能力 47→119 上涨(17.3→25.0);memory 通道贡献由正翻负,时间线与 §2.2 的记忆崩塌吻合(退化为 postmortem+口号后由助转害);replace 持平是两股力抵消。**注意所有差值均在 1-1.3σ(单格 SE ~4-5pp),方向自洽但统计不显著**,坐实需加采样(stateless avg@8 / replace 加题序)。

### 5.4 对后续实验的含义

1. **验证行为需要 reward 背书**,且刻度已知(§5.1):bonus ~0.1 或折扣平缓化;
2. **memory 积累需要"值得积累的数据"+"看得见积累的 reward"**(§5.3 两个推论);
3. **中期 ckpt(iter_47 附近)可能比末期 ckpt 更值得评测**:成功率峰值 + 验证纪律尚存 + 无模板坍缩;
4. 两个可独立修的小病:format_example 占位句改写(零成本);think 2048 上限加大或未闭合回退(防 CoT 泄漏)。
